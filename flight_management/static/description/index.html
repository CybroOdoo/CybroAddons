Flight Management

The foundational module for Flight Operations in Odoo 19 — flights, aircraft, and aerodrome reference data that every other Flight Operations module builds on.

Key Highlights

Flight Lifecycle Management

Every flight moves through a clear Draft → Scheduled → Dispatched → In Progress → Completed / Cancelled workflow, with guard rails at each step.

Aircraft Register

Track tail number, internal code, capacity, home base, and status (Active / In Maintenance / Grounded) for every aircraft in the fleet.

Manufacturer / Model / Class Structure

Aircraft are classified through a manufacturer → model → class hierarchy, so make and class are inherited automatically wherever they're needed.

Aerodrome Reference Data

Store ICAO/IATA codes, city, country, timezone, and coordinates for every airport used as an origin, destination, or home base.

Flight Event Timeline

Log takeoff, landing, gate out, gate in, and other timestamped phase markers directly against each flight.

Built-In Safety Checks

Validations block a flight from scheduling without an aircraft, dispatching without an active aircraft, or having identical origin and destination.

Can a flight be dispatched without an aircraft?

No. An aircraft must be assigned before a flight can move from Draft to Scheduled, and the assigned aircraft must be Active before the flight can be Dispatched.

Can origin and destination be the same aerodrome?

No, a validation blocks saving a flight where the origin and destination aerodromes are identical.

How are aircraft make and class assigned?

They're inherited automatically from the selected Aircraft Model, which itself belongs to a Manufacturer and, optionally, a Class — so you only pick the model once.

Is this module meant to be used standalone?

It works on its own for basic flight, aircraft, and aerodrome tracking, but it's designed as the foundation that other Flight Operations modules — scheduling, maintenance, and commercial — build on top of.
